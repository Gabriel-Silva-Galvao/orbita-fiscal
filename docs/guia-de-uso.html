Como usar a Órbita, do site à API

Clique, simule e confira cada recurso. Este guia cobre o que existe até a etapa 7d: o site inteiro ligado à API (Entrar, sessão, Checkout, Instalar e Portal), com a cobrança pela simulação do Asaas.

Dois modos. Sem variáveis de ambiente, o site roda em demonstração: tudo no navegador, código na tela. Com API_URL, PUBLIC_AUTH_ENDPOINT e PUBLIC_BILLING_ENDPOINT, criar conta, entrar, a sessão, sair, assinar e todo o Portal passam pela API (etapas 7b a 7d). Os itens do Portal que ainda não têm servidor (temas, áreas, novidades vistas, passos da instalação) continuam guardados no navegador. No cartão, o número ainda passa pela API da Órbita: serve à simulação, e a decisão para o Asaas real segue em aberto. Nenhum e-mail é enviado ainda: em desenvolvimento, o código aparece na tela.

Como rodar

Site (Astro), na pasta do projeto

npm install
npm run dev

Abre em http://localhost:4321.

API (Python FastAPI), na pasta api

python -m venv .venv; .venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000

Abre em http://localhost:8000, com a documentação automática em /docs. Copie .env.example para .env; em desenvolvimento, AUTH_CODIGO_NA_RESPOSTA=true devolve o código de 6 dígitos na resposta, já que ainda não há envio de e-mail.

Site ligado à API

No app do Claude, as configurações api e site-com-api de .claude/launch.json sobem os dois já ligados. No terminal, defina antes de npm run dev:

$env:API_URL="http://localhost:8000"; $env:PUBLIC_AUTH_ENDPOINT="http://localhost:8000/auth"; $env:PUBLIC_BILLING_ENDPOINT="http://localhost:8000/billing"; npm run dev

Com isso, /conta, /instalar e /assinar só abrem com sessão; sem ela, levam ao Entrar.

Plugin e servidor MCP

O cliente instala só o plugin, e o que se vende é a assinatura. O servidor MCP com a base jurídica já existe e será ligado depois; o site não depende dele. Até lá, "Baixar o plugin", "Gerar código de conexão" e os números do Status do plugin funcionam em demonstração, marcados "a definir". A lista de cada lugar está em docs/planejamento.md, seção "Servidor MCP".

SEO no ar

O site gera /sitemap-index.xml, serve /robots.txt e a imagem de compartilhamento /og.png. Para mudar a imagem ou o logo, edite scripts/og/og.html ou scripts/og/logo.html e rode npm run og. Razão social e CNPJ entram nos dados estruturados sozinhos quando forem preenchidos em src/data/site.ts. No dia da publicação: verificar o domínio no Google Search Console (registro TXT no DNS), enviar o sitemap e importar no Bing Webmaster Tools.
